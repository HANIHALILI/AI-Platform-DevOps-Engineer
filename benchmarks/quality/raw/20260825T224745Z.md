# Quality run

- Model: `agent-llm`
- Cases: `benchmarks/quality/cases.tsv`

## readiness_vs_liveness — PASS

A readiness probe determines if a container is ready to receive traffic, while a liveness probe checks if a container is still running and needs to be restarted.

## rag_grounding — PASS

Retrieval-augmented generation reduces hallucinations by incorporating retrieved sources to inform the generation process, ensuring accuracy. It encourages the model to abstain from making up information not supported by the retrieved sources.

## context_window — PASS

An LLM service uses a context-window limit to manage the amount of context it can process at once, which is determined by the number of tokens. This limit helps conserve resources by preventing the model from exceeding its capacity to handle input and output.

## quantization_tradeoff — PASS

4-bit quantization reduces memory and increases speed but lowers precision compared to 8-bit quantization. 8-bit quantization maintains higher precision and better performance but requires more memory and slower inference.

## parallel_requests — PASS

Increasing LLM parallel requests allows more tasks to be processed simultaneously, boosting throughput. However, each additional request consumes more memory, leading to higher overall memory usage.
